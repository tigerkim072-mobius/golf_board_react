# 스크린골프 점수판

Vite와 React로 만든 구장 로그인, 점수판 및 플레이어 등록 앱입니다.

## 실행

1. Firebase 웹 앱 설정을 프로젝트 루트의 `.env.local`에 입력합니다. `.env.example`을 복사해 사용할 수 있습니다.

   ```env
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=...
   VITE_FIREBASE_PROJECT_ID=...
   ```

2. Firestore의 `courts` 컬렉션에 구장 문서를 등록합니다. 각 문서에는 `이름`과 `암호` 문자열 필드를 사용합니다.
3. 구장 로그인 후 별도 `/games` 페이지에서 게임방을 선택하거나 새로 만들 수 있습니다. 새 게임방은 `gameRooms` 컬렉션에 구장 ID, 이름, 숫자 4자리 암호를 저장합니다. 게임방 삭제 시 이 암호를 확인합니다. 삭제해도 `scores` 컬렉션의 기존 점수 문서는 보존됩니다.
4. 플레이어 프로필(별명, `handicap`, 멀리건)은 `players` 컬렉션에 구장 ID와 함께 저장하고, 게임별 점수와 참가 상태는 `scores` 컬렉션에 플레이어 ID와 게임방 ID를 참조해 별도 저장합니다. 핸디캡의 표준 필드명은 `players.handicap`이며, 기존 `핸디` 필드는 이전 데이터 읽기에만 호환됩니다. 프로필을 수정하면 해당 기존 필드는 제거됩니다. 게임방에서 플레이어를 참가시키면 해당 방의 점수 문서만 생성됩니다. 기존 `scores` 컬렉션의 프로필 겸용 문서는 계속 읽을 수 있으며, 새로 등록·수정되는 프로필은 `players` 컬렉션에 저장됩니다.
5. Firestore에서 구장 문서 읽기, `gameRooms` 컬렉션 읽기/생성, `players` 컬렉션 읽기/쓰기/삭제, `scores` 컬렉션 읽기/쓰기, `users` 컬렉션의 `최고관리자` 필드 동등 조회 권한을 설정해야 합니다.
6. 설정 후 개발 서버를 실행합니다.

   ```sh
   npm install
   npm run dev
   ```

> **보안 주의:** 브라우저에서 Firestore의 암호를 확인하는 방식은 실제 인증/접근 제어가 아닙니다. Firestore 읽기 권한을 브라우저에 허용하면 사용자는 개발자 도구 등으로 암호를 확인할 수 있으며, 화면을 우회해 데이터에 접근할 수도 있습니다. 민감한 데이터 보호가 필요하다면 Firebase Authentication과 Firestore 보안 규칙 또는 신뢰할 수 있는 서버 측 암호 검증을 사용하세요. 암호를 Firestore에 평문으로 보관하지 마세요.

게임방 4자리 암호도 현재 Firestore 문서에 저장되며 브라우저에서 비교합니다. 따라서 암호 확인은 실질적인 보안 경계가 아니므로, 실제 삭제 권한은 Firestore 보안 규칙 또는 서버 측 검증으로 제한해야 합니다.

게임방 선택 화면의 `금요일 저녁 한겜` 방은 일반 등록 게임방으로 관리됩니다. 삭제하면 목록에서 제거되며 자동으로 다시 생성되지 않습니다.

## 관리자 페이지

`/admin` 또는 점수판 상단의 **관리자** 메뉴에서 관리자 페이지를 열 수 있습니다. 페이지에서 입력한 값은 Firestore `users` 컬렉션의 문자열 `최고관리자` 필드와 정확히 일치해야 관리자 화면이 표시됩니다. 이 비교는 브라우저에서 수행되므로 실제 인증이나 데이터 접근 제어가 아닙니다. Firestore 규칙에서 `users`를 넓게 읽을 수 있게 허용하면 해당 값이 노출될 수 있고, 클라이언트 상태를 조작해 관리자 화면도 우회할 수 있습니다. 실제 보호가 필요하다면 서버 측 암호 검증 또는 Firebase Authentication 커스텀 클레임을 사용하고, Firestore 보안 규칙에서도 관리자 권한을 검증하세요.

관리자 화면의 필드 통합 작업은 `players` 전체를 읽으며, 기존 `핸디`가 있으면 `handicap`에 복사(이미 값이 있으면 유지)하고 `핸디` 필드를 삭제합니다. 실행 전 확인을 거치며 되돌릴 수 없으므로 먼저 데이터를 백업하세요.

관리자 화면의 **프로필 이관 및 분리** 작업은 레거시 `scores`의 프로필 필드(별명, 핸디캡, 멀리건)를 `players`로 옮기고 `scores`에서 해당 필드를 제거합니다. 같은 플레이어의 여러 점수 문서는 `playerId`로 연결하며, 이미 `players`에 등록된 프로필은 덮어쓰지 않습니다. 점수, 게임방, 참가 상태, 방 번호 등 게임별 데이터는 `scores`에 유지됩니다. 구장 ID나 별명이 부족해 안전하게 연결할 수 없는 문서는 건너뜁니다. 실행 전 데이터를 백업하세요.

관리자 화면의 **scores 프로필 필드 삭제** 작업은 `scores` 컬렉션 전체에서 `name`, `nickname`, `handicap` 필드를 삭제합니다. `players` 문서는 변경하지 않으며, 실행 전 확인이 필요합니다. 삭제된 데이터는 복구할 수 없으므로 프로필 이관을 먼저 완료하고 백업한 뒤 실행하세요.

로그인 성공 시 구장 ID가 페이지 이동 상태로 전달됩니다. 플레이어 관리 화면은 `players` 컬렉션에서 `courtId`가 현재 로그인한 구장 ID와 일치하는 플레이어를 표시합니다. 구장 전체 명단은 게임방 간 공유되며, 점수판은 `scores` 컬렉션에서 별도로 해당 플레이어와 게임방에 연결된 점수 문서를 불러옵니다.

게임방 선택 후에는 구장 전체 플레이어를 참가 대기 목록에서 확인할 수 있으며, 점수판에서 참가 플레이어를 검색해 선택할 때 각 플레이어의 참가 방번호도 지정할 수 있습니다. 참가할 플레이어 선택창에서 새 플레이어를 추가하면 플레이어 프로필을 저장하고 선택한 방에 바로 참가시킵니다. 점수판에는 해당 게임방의 참가 플레이어와 점수만 표시됩니다. 점수판 하단의 초기화 버튼은 현재 표시 중인 게임의 참가자 점수를 0으로 만들거나 게임별 `mulliganUsed` 사용량을 0으로 초기화합니다. 두 동작 모두 실행 전 확인을 표시하고, 공용 플레이어 프로필의 멀리건 보유량은 변경하지 않습니다.
